Mappls tile URL finder BUILD 7 · callback handshake

Finds the raster tile URL for your Mappls key so the Mappls basemap can be switched on in Map Studio. Everything runs in this browser and talks only to sdk.mappls.com and apis.mappls.com — nothing is uploaded anywhere.

If the badge beside the title does not say BUILD 7, this page came from cache. Reload with a different query string — e.g. append ?7 to the address — to force a fresh copy.

1 · Ask the SDK what URL it uses

Loads the Mappls Web Maps SDK v3.0 from sdk.mappls.com — the host introduced with the August 2025 authentication change, which takes the Static Key as an access_token query parameter. Every network request the SDK makes is recorded, so the tile endpoint is captured whether the SDK uses <img>, fetch or XMLHttpRequest. When this works it is the definitive answer, because it is the URL Mappls themselves use.

2 · Try candidate layer names directly

The URL shape is documented — /advancedmaps/v1/<key>/<layer>/{z}/{x}/{y}.png — but the layer name for the road basemap is not. This requests one tile over Delhi for each candidate. Anything that renders an image is a working layer.

3 · List Styles API

This API is allocated on your account and should enumerate the styles/layers your key may use. Several request shapes are tried; any JSON that comes back is dumped raw.

4 · Read Mappls' own error text

When sections 1–3 all fail, the cause is authorisation rather than a wrong path: <script> and <img> requests are not subject to CORS, so if even those fail the server is rejecting the key. The browser hides the response body from this page, but not from a normal tab. Open these and read what Mappls actually says — the message names the problem (invalid key, wrong key type, domain not whitelisted, plan not entitled).

What to do with the result

Copy whichever URL came back green and paste it into MAPPLS_TILE_URL in js/config.js, replacing your key with {token} and the tile numbers with {z}/{x}/{y}. Then run node tools/stamp-assets.js and redeploy.
